# Pluto 2026-11-24: the frame .anl reader comes to pipestress, and a probe for its missing tables

Cloud session, mostly on branch `CalcFlow` (steel connection calcs from one STAAD `.anl`; its own record is on that branch). The user asked for the `.anl` parser work to be written to `pipestress`. This record covers that part.

> [!info]- What arrived in `scripts/lib/`
> - **`readers/AnlFrameReader.cs`** (from `CalcFlow`, 2026-11-06): a frame model's `.anl` read into `AnlFrameModel`: joints, members, sections, BETA, releases, offsets, supports, load cases and combinations, member end forces, STAAD's local axes and a joint index. `exporters/FramePackageWriter.cs` writes it as CSV files and a manifest.
> - **`AnlIndexer`:** an `.anl`'s sections now end at the next command echo (`LOAD LIST`, `PRINT ...`, `CHECK CODE` ...), so a member force section no longer runs on through a reaction print or the code check. A `.std` is indexed exactly as before (checked against the build before the change).
> - **`StaadModel`** opens a frame-only file.
>
> **New today, all additive:**
> - STAAD 2025's database form of a section (`TABLE 'W' ST 'W24X55'`) and double angles (`TABLE LD` / `SD`) read as their own families. The database form was read as section `ST` before.
> - Comment lines in the echo are skipped. They had truncated the joints and refused the properties.
> - `LOAD LIST` is parsed. Every output command is recorded in file order with the list it ran under (`AnlFrameModel.Prints`, `prints.csv`), and the ones whose tables are not read yet are named in one warning (`PRINT_NOT_READ`).
> - A force print in GLOBAL axes is refused. A line of a force table that holds numbers but is not a row is an error and is shown (`AnlForceParser.SuspectRows` counts them; the rows read are as before): the rows after it would be attributed to the member before. A member with forces at one end only is an error too.
> - A LOADTYPE of several words (`Roof Live`) is kept whole.

**The probe:** `scripts/lib/probes/anl-prints-probe.std`, with `README.md` beside it. A made-up frame printed with the usual output commands (code check, joint coordinates, member information and properties, support reactions, member forces, joint and section displacements, two load lists). After the usual prints it checks the code seven more times under other design parameters (AISC 360-16 ASD, a deflection check, 360-10, ASD 9th edition, LRFD 3rd edition, 360-05, 360-22), since the layout follows the code, the method and TRACK. Pluto's own `.std` reader parses it; STAAD has not run it yet.

**Verified here:** the strict C# 5 compile of lib + arms; the reader on scratch files for each new case. The reader's tests are on `CalcFlow` (`scripts/calcflow/tests/AnlFrame.Tests.ps1`), run against a build of this tree.

**The probe ran** (STAAD.Pro 2025; the user sent the `.anl`, committed beside the probe with the licensee and path lines removed). The reader took the real file as it is, and now also reads **support reactions** and **joint displacements** from it (`AnlFrameModel.Reactions`, `Displacements`; `reactions.csv`, `displacements.csv`). The README beside the probe says what each table looks like.

**Next:** from the probe's `.anl`, the parsers for the code check (a boxed block per member in AISC 360; older layouts for `CODE AISC` and `CODE LRFD`), section displacements and the two member tables.
