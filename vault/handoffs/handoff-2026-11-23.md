# Pluto 2026-11-23: a STAAD .std reads back into a frame model

Cloud session on branch `pipestress`. The user asked for a reader for the `.std` files Pluto writes, built by reusing
the STAAD lib's `.anl` reader rather than adding a second one. The .anl reader turned out to read less of the input
than expected: joints, incidences, groups, plate thicknesses, two PRIS values by group, spring supports and load
names, all as floats. It is now extended in place, and the frame side maps its output back.

> [!info]- The .anl reader, extended (`scripts/lib/readers/ANLReader.cs`)
> Additive: an `.anl` reads as before. The old and new reader give the same output on 200,000 random number lines,
> the STAAD probe, and a line-numbered echo of it with a page break. The progress output matches too.
> - `AnlIndexer.IndexFile(path, progress, extraMarkers)`: the `.std`'s own section markers (`StdMarkers`: `MEMBER
>   TRUSS`, `DEFINE REFERENCE LOADS`, `SELFWEIGHT`, `PDELTA` …), with no progress bar.
> - The block parsers take `Quiet`. The joint parser keeps exact coordinates (`Exact`) through a shared
>   number scanner (`ExtractDoubles` beside `ExtractFloats`).
> - The group parser records each group's kind and order, and the exact thicknesses. `Commands(section)` reads a
>   section as STAAD does: continuations joined, `;`, comments kept with the command after them.
> - `StaadInput.Read(path)`: the whole input, as data:
>   - units, joints, members, plates, groups and thicknesses, through those parsers;
>   - text parsers for materials, member properties, constants, offsets, releases, trusses and supports;
>   - reference and primary loads, combinations, the analysis;
>   - every command it does not take, as written.

> [!info]- The frame side
> - **`StdToFrame`** (`scripts/arms/frame/`): the inverse of `FrameStd`. It writes `.s2k` text, which `FrameS2k` reads, as
>   the CAESAR seed does. STAAD's commands are the model; the writer's comments give back SAP's labels and names.
>   - A frame whose PRIS is its section's with factors gets them back as property modifiers.
>   - Truss members become linear links. The zones' self weight is taken off the joint loads.
>   - A primary load's support displacements become a pattern of their own.
>   - A converted number is the shortest that writes back STAAD's digits.
>   - Exact or refused: [[vault/format/frame-to-staad|frame-to-staad]], "Reading a .std back".
> - **`FrameStd`** now writes:
>   - each property line's SAP section in a comment (a table section's SAP row too, which SAP needs to rebuild it);
>   - an area section comment over each thickness line;
>   - a label line for each material or group whose STAAD name differs.
>
>   It works the end zones' self weight out from the DENSITY and AX it writes. And it refuses a section with
>   modifiers of its own: it folded in only the frame's, so STAAD got other properties than SAP analyses. That was
>   a writer bug found on the way.
> - **`Build-Frame -In <x>.std`**: outputs `<name>_std.*`, never over the model the `.std` came from. `-Std` never
>   writes over the input. The read says whether the model, written back, gives the file's commands.

> [!info]- Tested here (mono `mcs -langversion:5`, PowerShell 7)
> These came back with every STAAD command the same:
> - the STAAD probe;
> - the linear rack, also with a catalog section, with P-Delta cases, and in kN / m;
> - a CAESAR seed with linear supports;
> - the probe without comments, and in STAAD's own layout (several joints a line, job information);
> - a hand edit.
>
> A file with seven foreign commands was refused with all seven named. The runner wrote every output from a `.std`,
> and the workbook made from it writes the same `.std`.
>
> Every vault diagram renders (Mermaid 10.9.1).
