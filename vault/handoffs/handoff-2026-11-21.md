# Pluto 2026-11-21: the audit's code issues fixed

Cloud session on branch `pipestress`, continuing [[vault/handoffs/handoff-2026-11-18|handoff-2026-11-18]]. Commits
`687ac1a` and `0d7738d`, both pushed.

> [!info]- The workbook overwrite question (`Build-Frame.ps1`, `Build-Pipe.ps1`)
> - `-Xlsx` and `-NewWorkbook` replace an existing workbook only when this runner wrote it and nobody has saved it
>   since: the stamp (`<base>.build.json`) now has an `xlsx` part with the file's fingerprint.
> - One with edits asks "Overwrite the workbook?" (Keep by default). Overwrite keeps the old one as `<base>.xlsx.bak`;
>   Keep writes nothing over it, and the rest of the run goes on.
> - With no one to ask (`-NonInteractive`, input redirected) the run stops before writing anything: `-Force` replaces
>   it with the `.bak`, `-Out` writes elsewhere.
> - Checked under PowerShell 7: unedited rerun (silent), edited and non-interactive (stopped, file unchanged), `-Force`
>   (the `.bak` is the edited file), asked in a terminal and answered Keep, then Overwrite.

> [!info]- A seed's additions keep its SAP settings (`FrameModel.cs`)
> A new object's row in a table no sheet shows copies the row every peer shares, when they all agree:
> - a new frame takes the auto mesh every other frame has: `AutoMesh=No` in a seed;
> - a case becoming nonlinear takes the parameters every other nonlinear case has: a seed's raised step limits.
>
> Checked by adding a frame and a nonlinear case in a seed's workbook. Reading a model is unchanged: the gate, both SAP
> exports read losslessly, and every test model's seed is byte-identical.

> [!info]- The viewer
> - **Auto range** works again: the Auto-reload checkbox (2026-10-22) had taken its id. It is `feaAutoReload` now.
> - **Find** takes an ID or a label, in both domains: a shell and a beam with one ID show the shell and say so, and
>   `b101` / `s101` picks the domain. Pipe and frame models, which have no shells, could find no element before.
> - **World coordinates:** `FEAFeatures.worldOffset()` reads `model.units`, as every exporter writes it. Saved
>   predicates were in the local frame: the sidecar now writes `predicates.version` 2, and a version-1 file's points are
>   moved by the offset once as they load (`test_predicates.js` T9).
> - Checked in Chromium on the rack (shells and beams), the SAP probe (text labels) and a CAESAR line; the 14 viewer
>   tests pass.

> [!info]- STAAD: an output only
> Nothing reads a `.std` into a frame model: the frame side writes STAAD (`-Std`) but does not read it. The older STAAD
> post-processing lib in `scripts/lib` (`ANLReader`, `StaadModel`, `scripts/Section-Cut.ps1`) reads STAAD's `.anl`
> results for plate models, for section cuts and design spreadsheets. It is a sanitized copy awaiting its project
> values on the production machine, with no arm note, and it is not wired to the frame model.
